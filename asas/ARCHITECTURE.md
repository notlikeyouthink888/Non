# معمار «أساس»

وثيقة مرجعية لكيفية تركيب التطبيق: الطبقات، نموذج البيانات، خط إنتاج التقرير، وقرارات التصميم.

---

## 1. الفكرة العامة

واجهة ويب (Vite + جافاسكربت خالص بلا إطار عمل) مغلّفة بـ Capacitor 7 لأندرويد.
الذكاء الاصطناعي عبر مكتبة Anthropic الرسمية (`@anthropic-ai/sdk`) من داخل الجهاز مباشرة
(أو عبر خادم وسيط اختياري)، والصور من واجهات ويكيميديا وOpenverse المفتوحة، والتصدير إلى Word بمكتبة `docx`.

```
┌──────────────────────────────────────────────────────────────┐
│ screens/   home · browse · create · report · library · settings │
├──────────────────────────────────────────────────────────────┤
│ report/    pipeline (خط الإنتاج) · compose (دون اتصال) · md · render · sheets │
│ ai/        client (Claude) · prompts            images/  sources · pipeline │
│ search/    محرك البحث العربي                     export/  docx · text        │
├──────────────────────────────────────────────────────────────┤
│ data/      types (17) · categories (16) · topics (323) · kb (76)             │
│ core/      store · db (IndexedDB) · arabic · dom · ui · nav · native · fmt   │
├──────────────────────────────────────────────────────────────┤
│ Capacitor: App (زر الرجوع) · Filesystem · Share · PrinterPlugin (يدوية)     │
└──────────────────────────────────────────────────────────────┘
```

## 2. البيانات

### أنواع التقارير — `data/types.js`
لكل نوع: اسم، وصف، وقائمة أقسام ثابتة `{ h: العنوان, g: إرشاد المحتوى, k: حقول قاعدة المعرفة }`،
واسم القسم الذي يحمل الخطوات المرقّمة، وعدد الصور الافتراضي. الهيكل نفسه يُعطى للذكاء الاصطناعي
(ليكتب العناوين حرفيًا) ويُستعمل للتأليف دون اتصال.

### العناوين — `data/topics.js`
صفوف مختصرة: `[المعرّف، العنوان، الإنجليزية، الأنواع المقترحة، مرادفات]`. الإنجليزية تُستعمل للبحث عن الصور،
والمرادفات تجمع العامية العراقية والأخطاء الشائعة.

### قاعدة المعرفة — `data/kb/`
٧٦ موضوعًا بحقول موحّدة: `intro, obj, std, app/equip, mat, prep, steps, calc{eq,vars,example}, table,
limits, notes, qc, safety, problems, kinds, pros, uses, img`. استعمالان:
1. **التأليف دون اتصال** (`report/compose.js`): كل قسم يأخذ أول حقل متاح من قائمة `k` الخاصة به، وما لا يغطيه يصبح إرشادًا بين `[ ]`.
2. **تأريض الذكاء الاصطناعي** (`ai/prompts.js → kbBrief`): ملخّص مضغوط يُرسل مع الطلب «اعتمد عليها ولا تخالف أرقامها».

## 3. خط إنتاج التقرير — `report/pipeline.js`

```
startGeneration(report, mode)            mode: ai | offline | images
 ├─ الكتابة ───────────────┐            (بالتوازي)
 │  ai: streamText → splitSections كل 120ms → عرض حي
 │  offline: composeOffline(kb)
 └─ الصور ─────────────────┘
    planFigures   (ai: JSON منظَّم | offline: kb.img)
    findCandidates → acceptable() → verifyLoadable()   ← تنزيل وفك حقيقي
    jsonCall(رؤية): يختار المطابق أو -1                 ← لا صورة خاطئة
    storeCandidate → IndexedDB (Blob + المصدر والرخصة)
```

- المهمة النشطة محفوظة في الذاكرة (`jobs`)؛ إن غادر المستخدم الشاشة وعاد، تشترك من جديد وتكمل العرض.
- إن أُغلق التطبيق أثناء الإنشاء، يُعلَّم التقرير «غير مكتمل» عند فتحه مع زر إعادة المحاولة.
- الصور مرتبطة بالقسم **بعنوانه** (`secTitle`) لا برقمه فقط، فتبقى في مكانها لو تغيّر ترتيب الأقسام.

### شكل التقرير المحفوظ
```js
{ id, title, typeId, topicId, catId,
  options: { length, level, images, details },
  meta: { author, university, college, department, stage, supervisor, date, org, project, location },
  source: 'ai' | 'offline', model, status: 'generating'|'ready'|'partial'|'error', error, notes[],
  sections: [{ h, md }],
  figures: [{ id, sec, secTitle, caption, queries[], mustShow, img, w, h, credit, cands[], status, note }],
  usage: { cost, output }, words, createdAt, updatedAt }
```

## 4. الذكاء الاصطناعي — `ai/`

كل الطلبات تبنيها `buildParams`:

| المعامل | القيمة | السبب |
|---|---|---|
| `model` | `claude-opus-5-5` افتراضيًا (Sonnet 5.5 / Haiku 5.5 اختيارًا) | الأدق للمحتوى الفني |
| `thinking` | `{ type: "adaptive" }` | النموذج يقرر مقدار التفكير |
| `output_config.effort` | من الإعدادات للكتابة (`high` افتراضيًا)، و`low` للمهام البسيطة | توازن الدقة والكلفة |
| `system` | نص ثابت تمامًا مع `cache_control` | تخزين مؤقت يخفّض الكلفة |
| `fallbacks: "default"` + `server-side-fallback-2026-07-01` | لـ Opus وSonnet | إعادة الطلب تلقائيًا عند رفض أمني خاطئ |
| `max_tokens` | 64000 للكتابة المتدفقة، 16000 لطلبات JSON | لا قطع للنص |

أنواع الطلبات:
- **كتابة التقرير**: متدفقة (`client.beta.messages.stream`)، نص Markdown مقيَّد (## للأقسام، ```eq للمعادلات، `[ ]` لما يحتاج تعديلًا). تُجمع الأجزاء بأنفسنا لأن التحويل لنموذج بديل يبدأ كتلة نصية جديدة.
- **تخطيط الصور، اقتراح العناوين، التحقق البصري، اختبار الاتصال**: مخرجات منظَّمة (`output_config.format` بمخطط JSON).
- **تحرير قسم**: متدفق بجهد أقل درجة.

الأخطاء تُترجم إلى رسائل عربية حسب نوعها (`aiErrorMessage`): مفتاح خاطئ، رصيد غير كافٍ، حد الطلبات، الخادم مشغول، لا اتصال، رفض.

## 5. البحث — `search/` و`core/arabic.js`

- توحيد الكتابة: أ/إ/آ ← ا، ى ← ي، ة ← ه، إزالة التشكيل والتطويل، الأرقام العربية ← لاتينية.
- تجذيع خفيف (ال، وال، بال… ات، ون، ين، ية…) ومرادفات عامية ← الصيغة المعتمدة.
- مطابقة: تامة ← بادئة ← مسافة ليفنشتاين (1 أو 2 حسب الطول).
- **وزن IDF**: الكلمات الشائعة («فحص») أخف من النادرة («هطول»)، فـ«فحص السلمب» تعطي فحص الهطول وحده لا كل الفحوصات.
- كلمات النوع («يومي»، «طريقة تنفيذ»، «مختبري») تُكتشف لاختيار نوع التقرير وتُحذف من مطابقة العناوين.

## 6. التصدير

- **Word** (`export/docx.js`): فقرات `bidirectional` ومقاطع `rightToLeft` بخط عربي للحروف المركبة (Simplified Arabic افتراضيًا)،
  جداول `visuallyRightToLeft`، الترقيم يُكتب نصًا صريحًا (يظهر صحيحًا في Word وWPS وLibreOffice وGoogle Docs)،
  صور مضمّنة من IndexedDB مع التعليق والمصدر، غلاف مستقل بلا ترويسة، ورقم صفحة في التذييل.
- **PDF**: نمط `@media print` في `styles/app.css` (غلاف بصفحة، فهرس، منع انقسام الصور والجداول).
  في المتصفح `window.print()`، وفي أندرويد إضافة `PrinterPlugin` تطبع WebView الحالي عبر `PrintManager`
  (لأن `window.print` لا يعمل داخل WebView) فيظهر خيار «حفظ بتنسيق PDF».
- **المشاركة والحفظ**: `@capacitor/share` و`@capacitor/filesystem` في أندرويد، والتنزيل في المتصفح.

مشكلة شائعة عولجت: النص اللاتيني بين قوسين في آخر سطر عربي «(Method Statement)» يظهر مقلوب الأقواس؛
`bidi()` تضيف علامة LRM بعد القوس في العرض وفي Word.

## 7. الفحص — `tools/check.mjs` و`tools/mocks.mjs`

متصفح Chromium بلا واجهة مع محاكيات تعترض الشبكة:
- **Claude**: يرد بتدفق SSE حقيقي الشكل (thinking ثم text) وبـ JSON حسب المخطط المطلوب، ويرفض المفتاح الذي فيه `bad` بـ 401،
  ويسجّل لكل طلب أي مخالفة لإرشادات الواجهة (النموذج، adaptive، effort، fallbacks، cache_control، رأس الوصول من المتصفح).
- **ويكيميديا/ويكيبيديا/Openverse**: نتائج تتضمن عمدًا شعارًا وصورة صغيرة ورابطًا معطوبًا (404) للتأكد من استبعادها،
  والتحقق البصري المحاكى يرفض آخر صورة للتأكد من أنها لا تُعرض.
- ملف Word الناتج يُفحص بـ python-docx: نسبة الفقرات RTL، عدد الصور، الجداول، التعليقات.

يعمل الفحص في GitHub Actions بوظيفة مستقلة عن بناء APK.

## 8. قرارات وأسبابها

- **بلا إطار عمل**: نفس نهج المشاريع السابقة؛ واجهة خفيفة وسريعة على الهواتف المتوسطة.
- **المفتاح في الجهاز أو خادم وسيط**: الاستعمال الشخصي لا يحتاج خادمًا؛ والمشاركة تحتاجه حتى لا يتسرب المفتاح.
- **Markdown مقيَّد لا JSON للكتابة**: يسمح بالعرض الحي أثناء التدفق، ومحلّله صغير ومتسامح.
- **صور محفوظة لا روابط**: الروابط الخارجية قد تنكسر أو تُحظر؛ الـ Blob في IndexedDB يُعرض دائمًا ويُضمَّن في Word وPDF.
- **رفض الصورة أفضل من صورة خاطئة**: الصورة غير المؤكدة لا تُوضع، ويُعرض بدلًا منها زر بحث يدوي.
- **Capacitor 7**: نفس بيئة البناء المجرّبة في CI لهذا المستودع (Node 20، JDK 21، Android 35).
